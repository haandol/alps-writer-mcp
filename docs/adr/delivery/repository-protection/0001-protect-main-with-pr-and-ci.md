# ADR 0001: main 갱신을 pull request와 필수 CI로 보호

Date: 2026-08-15

## Status

Accepted (2026-08-15)

## Context

로컬 hook은 빠른 피드백을 제공하지만 우회하거나 실행하지 않을 수 있다. 배포 경계가 로컬 관례에만 의존하면 테스트와 리뷰를 거치지 않은 변경이 main에 들어갈 수 있다.

## Decision Drivers

- main에 들어가는 모든 변경은 독립 리뷰를 거쳐야 한다.
- 필수 검증은 개발자 로컬 상태와 무관하게 실행돼야 한다.
- 긴급 우회는 일반 개발 경로가 되면 안 된다.
- 배포 규칙은 문서가 아니라 원격 저장소가 강제해야 한다.

## Decision

원격 저장소는 main 직접 갱신을 금지하고 pull request와 필수 CI 성공을 병합 조건으로 강제한다. 로컬 hook은 동일한 검증을 빠르게 실행하는 피드백 수단이며 최종 권한 경계가 아니다.

### Requirement contract

- main은 pull request 없이 갱신할 수 없다.
- 지정된 필수 CI가 모두 성공해야 병합할 수 있다.
- 필수 CI 설정 변경도 review 대상이다.
- 긴급 우회 권한은 저장소 관리자로 제한하고 사용 이력을 남긴다.
- 로컬 hook 우회가 원격 보호를 우회하지 못한다.

### Alternatives

1. **로컬 hook만 사용**
   - 장점: 설정이 단순하고 피드백이 빠르다.
   - 단점: hook을 실행하지 않거나 우회할 수 있다.

2. **CI는 실행하지만 main 직접 push 허용**
   - 장점: 긴급 변경이 빠르다.
   - 단점: 리뷰와 CI 완료 전에 main이 갱신될 수 있다.

3. **PR과 필수 CI를 원격에서 강제**
   - 장점: 모든 main 변경이 동일한 publication gate를 통과한다.
   - 단점: 원격 ruleset 관리가 필요하다.

## Consequences

### Positive

- 문서화된 협업 규칙이 실제 배포 경계에서 강제된다.
- 로컬 환경 차이가 publication 안전성에 영향을 주지 않는다.

### Negative

- 긴급 변경도 원격 보호 절차를 거쳐야 한다.

### Risks

- 관리자가 우회 권한을 일상적으로 사용할 수 있다. 권한을 제한하고 사용 기록을 감사한다.
