<inference_first>
Infer the smallest coherent solution and user flow from the approved Overview, references, domain
conventions, and reversible PoC defaults before asking. Ask only when several valid approaches would
materially change the PoC boundary or observable completion. Mark important inferred constants in
the approval digest.
</inference_first>

<questions>
1. What is the smallest product-level solution the user can try?
2. In the one core user flow, where does the persona start, what do they do, what becomes visible, and what marks completion?
</questions>

<workflow>
Read Section 1 and keep the same Primary Persona, core problem, value, and core hypothesis.

Keep Section 2 to two integrated inputs. Solution Strategy combines the product-level approach and
minimum user-visible PoC scope. Core User Flow defaults to one flow with a starting context,
sequential persona actions, visible product responses, and an observable completion result.

Add another flow only when the core hypothesis cannot be exercised without it. Follow the concrete
example in the Section 2 template. Do not write a capability inventory, implementation flow,
detailed state matrix, or edge-case catalog.
</workflow>
