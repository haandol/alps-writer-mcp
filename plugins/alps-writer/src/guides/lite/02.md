<section_guide number="2" title="Solution and Acceptance Tests" references="1">
<purpose>Turn the approved Overview into one minimum Solution Strategy and the Required Acceptance Tests the PoC must pass.</purpose>

<questions>
1. What is the smallest product-level solution the user can try?
2. Which product behaviors must this PoC demonstrate, and for each one what starts it, what does the user do, and what observable result makes it pass?
</questions>

<workflow>
Read Section 1 and keep its target user, core problem, value, and key assumption.

Ask one question at a time, or both only when the solution and required tests can be answered together.
Integrate the user's answer before presenting the approval digest.

Keep Section 2 to two inputs. Solution Strategy combines the product-level approach and minimum
user-visible PoC scope. Required Acceptance Tests list every behavior the first PoC must
demonstrate. Each test has a distinct name, starting condition, user action, and observable pass
condition.

Follow the complete multi-test example in the Section 2 template. Preserve confirmed values,
permissions, limits, and failure guarantees when they decide whether a test passes. Do not use
implementation functions, internal state, technical layers, or subjective impressions as pass
conditions.
</workflow>

<completion required="true">Confirm the Solution Strategy and every Required Acceptance Test before saving 2.1-2.2 separately.</completion>
</section_guide>
