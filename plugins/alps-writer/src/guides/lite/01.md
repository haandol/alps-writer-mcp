<section_guide number="1" title="Overview">
<purpose>Capture the minimum product overview through one Target User and Core Problem and one Value and Core Hypothesis.</purpose>

<inference_first>
Infer both inputs from the user's request, references, project context, and common domain framing
before asking. Ask only when multiple personas, problems, values, or hypotheses would materially
change the PoC. Mark important inferred constants with their basis in the approval digest.
</inference_first>

<questions>
1. Who is the single Primary Persona, what concrete problem are they facing, and what happens because of it?
2. What value should they gain, why does that matter to the team or organization, and what single belief should this PoC test?
</questions>

<workflow>
When several personas are presented, briefly name the candidates and ask the user to choose exactly
one Primary Persona before drafting or saving. Do not choose silently or combine candidates.

Keep Section 1 to two integrated inputs. Target User and Core Problem combines the persona, problem,
and present consequence. Value and Core Hypothesis combines the customer value, team or
organizational meaning, and one core belief to test.

Do not require a detailed current-alternative analysis, customer promise, metric, hypothesis list,
FAQ, feature list, architecture, or implementation plan. Use one short statement for each input
unless the user already supplied more detail.
</workflow>

<completion required="true">Confirm Target User and Core Problem and Value and Core Hypothesis before saving 1.1-1.2 separately.</completion>
</section_guide>
