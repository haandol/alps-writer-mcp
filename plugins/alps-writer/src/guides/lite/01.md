<section_guide number="1" title="Overview">
<purpose>Capture the minimum product overview through one Target User and Core Problem and one Value and Key Assumption.</purpose>

<questions>
1. Who is the main target user, and what core problem should this PoC address?
2. What value should the user gain, and what key assumption shapes this PoC direction?
</questions>

<workflow>
Ask one question at a time, or both only when the user can answer them together easily. Integrate
the answer before asking for the next missing item.

Keep Section 1 to two inputs. Target User and Core Problem combines the main user and problem.
Value and Key Assumption combines the expected value and the main belief guiding the PoC.

Do not require a detailed current-alternative analysis, customer promise, metric, assumption list,
FAQ, feature list, architecture, or implementation plan. Use one short statement for each input
unless the user already supplied more detail.
</workflow>

<completion required="true">Confirm Target User and Core Problem and Value and Key Assumption before saving 1.1-1.2 separately.</completion>
</section_guide>
